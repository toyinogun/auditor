# Product brief: AI Invoice Overpayment Auditor

A portfolio project. It must look and work like a real product, but it runs on fictional sample data only.

## What it is

A web app that finds money a company has overpaid its suppliers. Drop in supplier invoices, contracts and purchase orders; an LLM reads each one; plain code checks every invoice against the contract, goods received and the payment ledger; an analyst approves or rejects each finding and exports a claim list.

- **Audience:** finance and AP teams, procurement, recovery-audit firms.
- **Headline result:** "It read 12 documents and found $9,766.85 of overpayments in under a minute, with the evidence for every dollar."
- **In scope:** upload, LLM extraction, 6 checks, review screen, Excel/CSV export, an n8n intake workflow, a public demo URL.
- **Out of scope for v1:** logins and multi-tenancy, QuickBooks/Xero push (next step), real client data.
- **Time box:** 2 to 3 evenings.

## Features

1. **Intake.** Upload PDFs and CSVs in the browser, or drop them in a Google Drive folder that an n8n workflow watches and posts to the app's webhook.
2. **Classify and extract with an LLM.** One API call per document. The model gets one tool per document type (`record_invoice`, `record_contract`, `record_purchase_order`) and must call exactly one, so a single call both classifies and extracts. Validate the output with Zod. Scanned PDFs (no text layer) are sent as the file itself so the model reads the page images.
3. **Six checks, in plain code.** The LLM never calculates money.
   - Unit price above the contract in force on the invoice date
   - Duplicate invoices (invoice number with punctuation stripped, or same PO and same total), cross-checked with the payment ledger: paid twice means recover, unpaid means block payment
   - Billed quantity above quantity received, counted across partial invoices
   - Surcharge the contract doesn't permit, or above its cap
   - Freight billed when the contract includes freight
   - Invoice with no PO; SKU with no contract price (flag only, $0)
4. **Evidence on every finding.** Amount, a one-line calculation ("($5.10 − $4.85) × 1,500 = $375.00"), and the file and clause each figure comes from.
5. **Review screen.** Summary tiles (recoverable, approved, pending, % of invoiced), findings sorted by amount, a detail panel showing the invoice with flagged lines highlighted beside contract price and quantity received, Approve / Reject (a reason is required to reject).
6. **Export.** Finding log as .xlsx and .csv with the analyst's decisions and a total row.

## Stack

| Part | Choice |
| --- | --- |
| App | Next.js (App Router) + TypeScript + Tailwind |
| Extraction | Claude or Gemini API with tool use / structured output, schemas in Zod |
| PDF text | `pdf-parse` or `unpdf`; scanned PDFs sent to the model as files |
| Checks | Pure TypeScript functions in `lib/checks.ts` |
| Storage | SQLite with Drizzle |
| Export | `exceljs` |
| Intake | n8n: Google Drive trigger → HTTP Request to `/api/ingest`; workflow JSON committed to `n8n/intake.json` |
| Tests | Vitest |
| Hosting | k3s cluster behind a Cloudflare Tunnel (or Vercel), with a "Load sample data" button so visitors need no API key |

Data handling: documents go only to the model API, nothing to third-party storage, demo uses fictional data.

## Definition of done

- Tests assert all 8 findings and the 9,766.85 total
- A real LLM run on the sample PDFs matches offline mode
- A scanned (image-only) invoice still extracts correctly
- Approve / Reject works and the export reflects the decisions
- The n8n workflow picks up a file dropped in Drive
- Public demo URL, public GitHub repo with README and screenshot, 60 to 90 second screen recording
